# Firmware: `autogear_ml`

A dependency-free C99 library that runs the retained policy on the Shifter Pro's microcontroller
(Arduino Nano 33 BLE Sense Rev2, nRF52840, Cortex-M4F at 64 MHz). It is also an Arduino library
(`library.properties`), with an integration example in `examples/AutoGearML/`.

```
cadence, slope, acceleration, coasting (1 Hz)
   │  ag_features    14 gear-independent inputs; v_hat = cadence × development(engaged gear) / 60
   ▼
   ag_gbdt          100 boosted trees of depth 4 → target log-development (complete-tree arrays)
   ▼
   ag_controller    dead band h = 0.6, persistence k = 3 s, one step at a time, never while coasting
   ▼
servo: −1 / 0 / +1
```

## Footprint (arm-none-eabi-gcc 14.2, `-Os -mcpu=cortex-m4 -mfloat-abi=hard -mfpu=fpv4-sp-d16`)

| Module | Flash (bytes) | RAM (bytes) |
|---|---:|---:|
| `ag_model_data.c` — 1,500 thresholds, 1,500 feature indices, 1,600 leaves, bias | 13,904 | 0 |
| `ag_gbdt.c` — inference | 116 | 0 |
| `ag_features.c` — 14 inputs, 16-sample ring buffers | 520 | 224 |
| `ag_controller.c` — hysteresis controller | 404 | 92 |
| **Total** | **14,944** | **316** |

A prediction is exactly 400 comparisons and 100 single-precision additions, the same for every
input: no heap, no recursion, no data-dependent memory layout, no runtime library.

## Model layout

Each tree is stored as a *complete* binary tree of depth 4: node `i` has children `2i+1`
(`x < threshold`) and `2i+2`, the XGBoost convention, so no child pointers are needed. Branches
that training pruned early are padded with `+INFINITY` thresholds and repeated leaf values. The
arrays are generated by `scripts/09_export_firmware_model.py` from the model trained on the whole
dataset, and checked there against XGBoost's own predictions (maximum difference: 0).

## Verification against the Python reference

```
python scripts/09_export_firmware_model.py   # writes ag_model_data.{h,c} and host_test/vectors.csv
make -C firmware test                        # gcc build of the library + host_test.c
make -C firmware size                        # needs arm-none-eabi-gcc on the PATH
```

`host_test` replays three rides (14,261 s) and checks four things:

| Check | Result |
|---|---|
| C inference on the Python inputs vs Python prediction | identical (max diff 0) |
| C inputs computed from raw signals vs Python inputs | max diff 2.9 × 10⁻⁶ |
| C controller fed with the Python targets vs Python gears | identical at every second |
| Full device loop in C (cadence produced by the device's own gear) vs Python replay | same gear 99.71 % of seconds, within one gear 100 % |

## Status

The library is verified on the host. The Arduino sketch in `examples/` shows the integration with
the IMU, the barometer, the Hall sensor and the servo, but it has **not been run on the bicycle**:
the AutoGear prototype is no longer available. Sensor calibration, servo angles and the gear ladder
in the sketch are placeholders.
